# Design Guidelines

- Start Codex account sessions immediately using the plugins already installed in that profile. Do not automatically synchronize plugins from the default Codex home. Close the launcher immediately when a valid session is requested; ignore repeated requests for the same project, agent profile and task while its launch is pending.

- In Manage, show each section (Terminal, Agents, Your accounts, Models and effort) as one bordered table with rules between rows, its uppercase label aligned with the table's left edge, under a one-line description. Keep each account compact: Rename, Shared plugins and skills… (local Devkits Codex rows only) and Remove sit in a ⋯ menu at the end of the row, without a separate sync row or permanent explanatory text; Add account on the base Codex and Claude rows is a 28px secondary button, matching the selects. Shared plugins and skills… opens a 640px native Sera selection dialog with a bordered table of individual local/Git marketplace plugins and legacy custom skills from ~/.codex, grouped as PLUGINS and SKILLS. Keep NAME, SOURCE and STATUS columns aligned, with a flexible name column, fixed 140px source and 108px status columns, a fixed header and scrolling 36px rows separated by thin rules. Put the All checkbox in the table header. Restore that profile's existing selection; new items start unchecked. An All checkbox above the groups selects or clears every available item without running synchronization. While opening this dialog, show Checking shared settings… and inspect actual links, plugin settings and marketplace settings. Display Synced, Update needed, Conflict, Not shared or Source missing beside each item, independently of its selection; checking never applies changes. Only Sync applies checked items, and unchecking stops sharing previously imported items while preserving source files. Link individual plugin folders, never a whole marketplace; ~/.agents/skills is already shared. Keep short scope guidance in this dialog, show errors there, and return to Manage with a notification after success. Opening Manage or starting a session never synchronizes. Read/write settings through Codex's version-checked API with a one-time backup, preserving private settings. Keep remote plugins, credentials, system skills, plugin data, conversations, databases and temporary/runtime folders independent; refuse conflicting real files or foreign links.

- Token statistics has an All, Codex and Claude provider selector above the fixed summary, with each provider's existing program icon beside its name. The selected provider filters token totals, estimated cost, daily bars and every table together. Changing providers clears model and account filters, retains the date range and day/project filters, and returns to the first table page. Clear filters also returns the provider to All.

- Token statistics keeps the total estimated USD alongside the token totals in a fixed summary above the scrolling chart and tables, following the selected date range and filters. Each Models, Projects, Accounts and Sessions row also shows estimated USD. Use a bundled, dated table of official standard API token rates, separating uncached input, output and cache reads/writes without counting reasoning twice. Preserve Claude's recorded one-hour cache writes; otherwise assume short cache TTL. Explain that this is API equivalent cost, not subscription charges, and excludes long-context, speed, region, tools and tax adjustments. Unknown model IDs have no guessed price: leave wholly unpriced amounts blank. Show known subtotals as right-aligned currency only, with no question marks, pricing-status labels or excluded-token messages. Keep token totals and daily charts unchanged.

- Open Token statistics from a chart icon beside Manage agent profiles in the AGENT PROFILES header. Use a large native Sera dialog with Today, 7 days, 30 days and All time ranges, token totals, clickable daily bars, and Models, Projects, Accounts and Sessions tables. Clicking a day or grouped row filters the results; Clear filters resets them. Paginate tables and refresh local history once a minute, retaining the last successful result during refresh or errors. Allow wheel and trackpad scrolling without a visible scrollbar. Clicking the backdrop, Done or Escape closes the statistics dialog. Separate uncached input, output, cache read and cache write; include reasoning in output. Format token totals and table values consistently with one-decimal K/M/B suffixes; retain exact counts in accessibility labels. Read local Codex and Claude history, including dedicated Herdr profiles, without depending on Orca or provider services. Label unknown metadata explicitly and do not present token totals as subscription charges.

- Use Project consistently for the folder-backed session container in user-facing navigation, menus, dialogs, and status text.

- Prefer a thread's explicit task name or live agent title over launcher/account labels. Use the account label only as a fallback when there is no thread title. Drop the repository Codex appends to its terminal title ("Task | repo") so Codex and Claude titles match.
- Do not show hover tooltips anywhere in the custom interface or shortcut hints beside Add session entries. Keep keyboard shortcuts and accessibility labels.

- Within each project's thread list, show threads with working agents first, preserving the original tab order within each group. Recompute from live status so finished threads return to their original order.
- Show a thread's close button only while its row is hovered, including selected threads. Reserve its fixed-width trailing slot while hidden; a leave event from another row must not clear the currently hovered row.
- Give every thread one leading icon, centered at 14px in a fixed 16px slot. While any agent in the thread is working, replace its program icon with a native rotating spinner in the working color. Otherwise show its own program icon (or the terminal icon for a shell), including when done, blocked, idle or unknown. Do not show a trailing status icon. Stop the animation when no agent is working.

- The usage area sits below the threads list and above the sidebar settings footer, with vertically stacked full-width account rows and content-sized height. It follows Add session's visible entries and section order, including Terminal. Always show a meter track; label unsupported providers as Not supported and missing quotas as unavailable. Show separate labeled five-hour and weekly meters only for windows the account actually returns; weekly-only accounts show only Week. Size each account row to its content and top-align its text, without fixed row heights or calculated section heights. Label the section AGENT PROFILES and place a settings icon button with the accessible label Manage agent profiles in its header that opens the existing profile management dialog. Before it, a refresh icon button labelled Refresh agent profiles rediscovers profiles and rereads every shown account's usage immediately, bypassing the Codex cache; it is disabled while usage is loading. Vertically center the program icon within its row and use a 12px semibold foreground account name. Beside each meter, retain the used percentage and show reset countdowns in hours/minutes below a day or days/hours for longer waits (for example, Resets in 6d 21h). Use the existing minute refresh to update countdowns without hiding cached usage; expired resets say Reset due until fresh data arrives. Use green below 70% used, amber from 70%, and red from 90%, consistently in the sidebar and details. Only local Codex accounts and Devkits Claude accounts show quotas. Cache each Codex result locally for 5 minutes, across reloads and restarts, so reloading never queries providers again; keep the last good windows when a later read fails. Read Claude quotas only from what Claude Code passes to the profile's status line, never from credentials or a usage API. In the built-in Claude profile, keep any existing command status line working by chaining it after recording, with a one-time settings backup. Keep visibility and ordering in Add session’s Manage dialog; reuse that same dialog from the section header; do not add hover tooltips. Clicking an entry opens a usage details dialog that also closes when clicking the backdrop, with all returned quota windows, used and remaining percentages, reset times, last update, and errors. Use the same live reset countdowns for every quota window in the details dialog, refreshed every minute while open. Refresh once a minute and when the selection changes; identify five-hour windows by their actual duration.

- Compare quota usage with elapsed time within the same quota window: use 10px-high meters in the sidebar and details, split into two equal-height bands, with muted time progress and its thin vertical marker in the top half and colored quota usage in the bottom half. Add faint 1px ticks only in the time band: five equal segments for 5h (one hour each) and seven for Week (one day each), without numeric labels; retain the stronger current-time marker. Keep meters and each details entry from shrinking. Open details at 480px high so the usual two windows fit; scroll additional windows while keeping the title and footer visible. Calculate time progress from the returned reset time and actual duration; hide it for missing, inconsistent, or expired windows while retaining cached usage. Refresh with the existing minute timer in the sidebar and details, and explain the two halves in details. This is a pacing reference for the whole quota window, not today's usage or a prediction.

- Use a consistent **shadcn/ui Sera visual language across the entire interface**, including menus, dialogs, sidebars, headers, and empty states. Styling a few controls is not enough.
- Follow Sera’s editorial geometry: square corners throughout controls, menus, dialogs, meters, and terminal panes; thin borders and no decorative shadows. Retain Neutral colors and semantic theme tokens. Use Georgia serif for dialog, empty-state, and brand headings, with Geist sans-serif body text. Use small uppercase menu section labels; preserve account and project display names. Use bottom borders for outlined actions, selects, project pickers, and text inputs. Keep hover, focus, and selection states consistent. Native GPUI does not expose letter spacing, so use uppercase labels without simulated spacing.
- Prefer compact layouts, aligned edges, and clear visual hierarchy. Avoid redundant labels when an icon or nearby context already conveys the information.
- Let the terminal fill the central workspace without outer padding or a pane frame. Keep a compact 32px title row showing the current thread title, program icon, and the muted agent profile that started it (omitted when it repeats the title), without a status badge or split, zoom, or close controls. Align it with the sidebar's 32px project header. Keep only the terminal's text padding.
- Make thread hover and selection backgrounds span the sidebar width, with no horizontal row margins. Use a consistent 12px content inset for project headers and thread rows, without extra top padding or gaps between rows.
- Separate adjacent project groups with a full-width 1px line using the border theme token, without an extra gap or a line above the first group.
- Reorder projects in Threads through Move up and Move down in each project's menu, disabling moves at the list boundaries. Save changes immediately and preserve project selection, thread order, and header click-to-collapse behavior. Keep reorder handles out of project headers.
- Open session visibility and ordering management in a large modal dialog from the bottom of Add session (680px wide, 80% of the window height). Keep Terminal, built-in agents, and user-added accounts in separate sections in both Manage and Add session, in that order. Show each entry's program icon beside a Sera-style square checkbox (solid primary fill and contrasting check when selected). Reorder within a section using drag handles or Alt + Up/Down; commit on drop and cancel a drag on Escape or leaving the dialog. Terminal stays in its own section. Avoid a persistent scrollbar; scroll only when the list exceeds the available height. Save changes immediately; clicking the backdrop, Done, or Escape closes Manage when no drag is active.
- Open Asana tasks from the first item of a local project's menu, followed by a separator; it replaces the terminals like Files and Changes, closes from its toolbar, and selecting a session returns to terminals. Each Devkits project binds one Asana project, chosen from a searchable dropdown under the project button at the start of the toolbar (Asana typeahead); until one is chosen the content explains where to choose it. Show only Loading until the saved token has been read. Show the project read only, like Asana and Linear: a remembered List or Board view grouped by Asana sections in Asana's order, Mine, All and Saved views (Mine, the default, shows tasks assigned to the token owner; the choice is remembered), and search. Load only what is shown: Mine asks Asana for the token owner's open tasks in the workspace and keeps this project's; All loads one 100-task page when first shown and another from Load more at the end of the List or Board. The List stays a plain scroll list rather than a virtual list: paging keeps it small, and a virtual list rebuilds visible rows in script on every hover frame, which lags. Follow Linear's look: section headers and cards carry a status icon derived from the section name (todo, in progress, backlog, done); List rows are borderless 36px rows with status, title, a subtask count chip that expands sub-issues, then saved star, short due date (red when overdue) and an avatar of white initials on a steady per-person color; Board columns are sections with bordered cards. Never store issues, statuses or columns locally and never drag cards. Selecting a task opens a preview on the right, like Linear's issue peek (half the width by default; drag the divider to resize, keeping 320px on each side, and remember the width), read fresh from Asana: a breadcrumb to the project and parent, a large title, Status, Assignee and Due date as label and value rows, the description, a bordered Sub-issues list, and an Activity section with the task's comments (author avatar, name, relative time, selectable text; loaded after the preview opens), with Open in Asana and Save for later in its header and, at its foot, an auto-growing instructions box (a draft kept per task while Devkits runs) above Agent, Model and Effort selects and Start session. Agent lists the visible local Add session agents; Model and Effort default to the agent profile's defaults, named in the option (for example Default (Opus)), and offer Claude's model aliases and efforts, or the models and per-model efforts in that Codex profile's models_cache.json; other agents show no Model or Effort. The last choice is remembered. In Manage, each Claude or Codex profile row is one block of two lines sharing hover and selection: the name and its actions, then a settings line aligned with the name holding equal 168px Permissions, Model and Effort selects with muted labels above their triggers and only the chosen value inside (Model and Effort for local profiles only). Model and Effort set its default for every new session, from Add session or Asana, unless a session picks its own; Default adds no flag and leaves the profile's own configuration. A MODELS AND EFFORT section at the end of Manage, for local projects with Claude or Codex launchers, has one bordered card per provider, like Cursor's model list: a header with the shown count, one 36px row per model with a drag handle (dragging sets the Model menu order; models Codex adds later follow in their own order), its name, Codex slug and effort range and a square Switch on the right, and an Effort row of joined ToggleGroup segments as in Claude Code and Codex (Codex merges every local profile's cache); unchecked ones are hidden from the composer by key, so models Codex adds later still appear, and Default always remains. Save for later only bookmarks the task on this computer, per Devkits project; Saved drops deleted or completed tasks, keeps tasks that became subtasks, and dims tasks moved out of the project. Start session starts the chosen agent directly, adding --model/--effort for Claude or -m and model_reasoning_effort for Codex after its executable; the task names the thread, its name, link, parent, description and latest five comments (each shortened to 500 characters), followed by the typed instructions, become the opening prompt, and it leaves Saved. A thread started from a task remembers that task (matched to its tab like the agent profile, never showing the task ID); its pane title row shows a bordered Asana chip beside the status that opens the thread's project on the Asana panel with that task in the preview. Asana is never changed. Ask for a personal access token in the panel when none is saved or Asana rejects it, saving it only on this computer.
- Profile defaults use that profile's Codex model cache and supported efforts; changing its model clears an incompatible saved effort. Asana narrows efforts to the effective model, including an inherited default, and omits an incompatible inherited effort when a session overrides the model. Model and effort availability switches filter both profile defaults and the Asana composer. Disabling an item clears matching profile defaults to Default and prevents new sessions from adding that item as an override. Explicit launch settings replace conflicting model and effort flags while retaining unrelated launcher arguments.
- Put Add account on the base Codex and Claude rows in Manage, only for local projects. Each provider signs in through its official CLI into a dedicated credentials directory; a Claude sign-in dialog also accepts a pasted authentication code. Account sign-in returns to Manage after completion or cancellation, refreshing the account list. Keep account creation out of the Add session menu and individual account rows.
- Use a native Select for default permissions on the settings line under each Codex or Claude profile row. Label each select (Permissions, Model, Effort) above its trigger. In Manage the triggers are bordered 28px fields (colored value, muted chevron) lined up with the profile name, hovering with the stronger input background; elsewhere, such as Asana, the trigger keeps its underline. Show only option names: Default (neutral), Read only (blue), Workspace (green), Full access (red). Color the selected trigger and options; keep permission descriptions in the data without displaying hover tooltips. Do not open a permissions details dialog or show subtitles. Save per launcher and apply only to new sessions; Default preserves the existing launch command and Codex configuration. Leave other providers without this control.
- Label the outlined button on user-added account rows Remove; explain sign-out in the confirmation dialog. Sign out the account's dedicated credentials before removing its program entry; preserve history, project files, other accounts and running sessions. Show failures and retain the entry for retry when removal cannot complete.
- Open dropdowns 4px below their trigger: align project pickers and primary actions to the left edge, and sidebar icon menus to the right edge. Use the trigger's measured bounds and native window-edge fitting. Contain each native Popup's trigger-measurement canvas in a relative, non-shrinking host. Keep side and start/end alignment explicit; the Git footer menu opens above with its right edge aligned to the arrow, growing left into the window. Native fitting must keep menus inside the viewport when space is limited. Account names and hosts use separate lines with an aligned selection check; constrain menu text to its available width with ellipsis.
- Let Add session expand to its content height, including every visible section and the Manage action. Do not cap its height or put its session list in a scroll container.
- Use Zed as the reference for project, workspace, and thread interactions. Follow its placement and behavior when relevant, rather than loosely borrowing its appearance.
- In Changes, retain the editor header and right dock when there is no diff. Show a single centered, muted 13px Geist message, without a serif heading or redundant explanation; hide Unified/Split and line totals until there are changes. Use the same compact typography for loading and errors.
- Keep a Diff options menu in the editor header, including when no files are visible. Hide lock files is checked by default and remembered across projects and restarts. Filter dependency lockfiles (including Cargo.lock, yarn.lock, package-lock.json, pnpm-lock.yaml, npm-shrinkwrap.json and Bun lockfiles) from both the working diff and commit preview, and from the Changes tree and its counts. Keep the underlying Git changes intact. When every changed file is hidden, explain the filter in the empty message so it can be turned off from the menu.
- Include a checked Wrap option in the same Diff options menu. Remember it across projects and restarts, applying to Unified, Split and commit previews. With Wrap enabled, soft-wrap to the viewport as before; with it disabled, retain one visual row per source line and allow horizontal scrolling across the diff. Keep split sides aligned, line numbers and word highlights intact, and the Git dock outside the horizontal scroll area.
- Show Unified and Split as two compact 24px icon buttons in the diff header, following Zed's stacked-block and side-by-side-block symbols. Use 16px icons and retain the selected background and accessible mode labels without hover tooltips.
- During the initial Changes read, show Loading changes only in the center of the editor. Keep the Git footer at its usual height with a branch placeholder and disabled Fetch; do not add a Loading branch row that shifts the footer when it disappears.
- Show the Git panel's branch immediately from the same live project metadata used by the status bar, without waiting for diff or upstream queries. Follow native branch updates while the panel stays open; use the repository read as a fallback when native metadata has no branch.
- In both Changes and commit previews, keep file title bars full width with only a bottom border, so their top edge does not double the separator below the editor header or commit details. Keep the 32px title height and existing gaps between files.
- Put Changes and History tabs in the right Git panel's 32px header, with the branch and Git actions footer shared by both. History shows the current HEAD's commits in a virtual list with subject, author, short SHA and time, loading batches of 50 from a fixed revision so new commits cannot duplicate or skip entries. Automatically load the next batch when scrolling reaches the list's end or keyboard navigation approaches it; show only a temporary Loading row, with no Load more control. Prevent duplicate requests and retain Retry for failed reads. Selecting a commit shows its full message and metadata above the existing unified/split diff on the left; root commits compare to the empty tree and merges to their first parent. Switching back to Changes restores the working diff. Load history only when opened, refresh it after HEAD changes, retain successful lists and previews during background reads or errors, and ignore late results after changing project or selection. Keep loading and empty-history messages inside the history area, never in the footer. Do not add a service connection or fetch automatically.
- Keep the current branch and a compact 26px solid remote-action split button in a 38px fixed footer of Changes' right Git panel, including when there are no uncommitted changes. Use 10px horizontal padding and a separate 24px-wide chevron button. Follow Zed's state transitions: Fetch when synchronized, Push when only ahead, Pull whenever behind (including divergence), Publish without an upstream, and Republish when the configured upstream ref is gone. Show positive counts before the label, behind as ↓N then ahead as ↑N; hide zero counts and counts without a comparable upstream. Calculate from local Git refs and refresh after commits, fetches and remote operations without automatically fetching. Fetch runs git fetch --all without merging; Fetch From lists remotes and an All option when there are several. The chevron always offers Fetch, Fetch From, Pull, Pull (Rebase), Push, Push To and Force Push (with lease). Publish and Republish push the current branch with --set-upstream; Push and Push To also publish when the upstream is missing. Prefer the configured push remote, then origin or the sole remote; otherwise open the existing remote picker. Use existing Git configuration for tracked pushes and pulls, and --force-with-lease for force pushes. Disable concurrent operations and unavailable actions, while keeping Fetch available on detached HEAD and before the first commit when a remote exists. Show progress on the button. Keep the Git footer fixed at 38px, with no result or error rows below it. Show operation results in a compact, dismissible floating toast above the footer; successes disappear after five seconds, while failures remain until dismissed or retried. Failure toasts show a short action title, an error icon and View Log, which opens the complete Git output in a read-only central editor with a close button returning to the prior diff. Keep the Git panel available, retain failures for retry, and clear project-specific output and notifications when changing projects. Use a brief native notification if an operation finishes after leaving its project. Support keyboard navigation, Escape and outside-click dismissal, with no hover tooltips.
- Add GitHub account to the Git action menu, opening a submenu of accounts already signed in through gh on the project's machine, with Default, the selected account marked, unavailable accounts disabled, and Refresh/Retry. Remember only host and login per machine and project folder. Default preserves existing Git authentication. A chosen account applies to that host for each Fetch, Pull, Push or publish operation through a temporary Git credential helper that requests gh's token for that user; never switch gh's active account or save credentials in mod state. Use HTTPS for that host, translating conventional GitHub SSH URLs for the operation only, without editing remotes or Git configuration. Load account metadata on opening the submenu, ignore results from a previous project, and keep the Git footer's height unchanged.
- Leave the content area completely blank in an empty workspace, without a centered icon, project name, path, prompt, or Add session button; use the project's sidebar + to start a session.
- Opening a new project creates a Herdr space with a default terminal immediately. Mark this internal tab at creation and remember its ID; omit it from the thread list while keeping it running. User-created terminals remain visible, as do agents running in the default tab. Subsequent agent sessions use separate tabs. Reopening an existing project selects its space without creating another terminal.
- When the internal default terminal is selected, leave the content area blank; closing the last visible thread returns to this empty workspace while its space stays open.
- Leave the sidebar's project list blank when no workspace is open; omit the Open a project empty state and its Open folder button.
- Implement the design with Herdr's native GPUI components. Do not introduce React, a webview, or runtime UI dependencies just to reproduce the style.
- In header and status bars, pickers and icon buttons fill the bar's height with square corners, and the outermost control sits flush with the bar's edge, so hover backgrounds are vertically centered and reach the edge: the window header's project switcher and window buttons, the simulator header, the Changes and Git output headers, the AGENT PROFILES header and the status bar. Icon buttons there are as wide as the bar is tall. Pickers ending in a chevron use 10px left and 6px right padding, since the chevron icon carries its own space. Secondary text actions (Cancel, Retry, Previous/Next, Clear filters, View log, Add account, Select …, Delete…) are bordered so they read as buttons before hover, and hover with the input background; ghost text is kept only for segmented choices and tabs, and Asana keeps its own buttons. Buttons inside a row that itself hovers (thread close, project + and ⋯, a booted simulator's power button) hover with the stronger input background and foreground icon, so they read as separate targets from the row. Segmented choices, search fields and text buttons keep their own height, and the Asana panel keeps its own controls.
- Toggle project files from the folder icon at the right of the status bar, with a selected background while open. Show a compact file tree on the right and a native read-only editor on the left, with soft wrapping enabled. Toggling files off or selecting a session returns to terminals. Each project remembers which panel (Files, Changes or Asana tasks) it last had open and restores it when the project is selected again; choosing a thread, starting a session or closing the panel there forgets it. Keep file navigation independent of starting a session. Watch local project files and update the tree and current preview automatically, preserving expanded folders and the current selection. Coalesce bursts of changes (300ms for Files, 500ms for Changes) and, as Zed does, keep the current tree, colors and diff on screen while refreshing: show Loading only for a first read, and repaint only when the result differs. Use a 10-second polling fallback for remote folders or unavailable native watching. Do not show a Refresh button.
- On macOS, toggle a live iOS Simulator panel from a phone icon left of the Changes and Files icons in the status bar, with the same selected background while open. It is a resizable column (380px default, 300–900px) to the right of the workspace and between the window header and status bar, so terminals, Files and Changes stay beside it; it is not per project and Herdr remembers whether it is shown. Its 32px header holds a borderless device picker (status dot, name · iOS version, chevron) opening a dropdown of available simulators, most recently used first, each showing its iOS version and relative last use, and never-used ones last under a separator and a NEVER USED label, with booted ones marked and a power button on each booted row that shuts that simulator down, plus Repair input for the chosen booted device and Xcode storage…, an open-in-window button and a close button. Herdr cannot embed a web view and its file-image frames lag about 0.2s, so open-in-window shows serve-sim's own 60 FPS preview of the device, always with its device frame, in a Chrome app window (the default browser without Chrome) for smooth interaction. Whenever another client (such as that window) is connected to the device's serve-sim helper, regardless of focus, the panel pauses its own stream like a hidden panel, keeps the helper and header usable, and says the device is showing in the preview window; it checks connections with lsof at most every two seconds (no Automation permission) and resumes once the window closes. Below are centered Home, Lock, Volume down/up, Rotate and software-keyboard icon buttons, then the screen in a dark bezel keeping the device's aspect ratio. Click to tap, drag to swipe, scroll with the wheel and type once the screen is clicked; Cmd chords stay Herdr's. Choosing a shut-down simulator boots it. Stream through serve-sim (adapted from herdr-sim) only while the panel shows, write frames into the separate devkits-sim-frames mod folder so the mod does not reload, and stop helpers Devkits started when the panel closes. Android emulators are not supported.
- Open Xcode storage from Xcode storage… at the bottom of the simulator panel's device picker, below Repair input. It is a large native dialog measuring ~/Library/Developer: Total, DerivedData, Simulators, Runtimes and Archives sizes above one scrolling list. DerivedData is grouped by project, largest first, each folder labelled by its workspace (home shortened to ~, EAS local builds as EAS local build <id>) with Workspace missing, Shared cache, last use and size. Folders whose workspace no longer exists start checked on the first scan, and Select … with missing workspace checks them again. Simulators are grouped as Recently used (booted or used in the last 7 days), Not used for 7+ days and Never used, largest first, each with a relative last use (Today, 4 days ago, Never used), date and size; group headers check every selectable simulator in the group, and booted ones show but cannot be selected. Runtimes and Archives are size only, pointing to Xcode's Components settings and Organizer. Delete… asks for confirmation in the footer with the item count and size; only DerivedData folders and shut-down simulators (via simctl delete) are removed, then the dialog rescans and posts a notification. Never delete automatically.
- Toggle uncommitted changes from a compare icon beside the file toggle in the status bar, with the same selected background; it and Files replace each other, and selecting a session returns to terminals. Copy Zed's project diff: one continuous, virtualized multibuffer of every changed file against HEAD, including untracked files, with fixed-height visual rows so wrapped content scrolls correctly. Each file has a 32px header with its name, muted folder, New/Deleted label and +/− counts, separated from the previous file by an 8px gap, and collapses or expands on click. Hunks show three lines of context without @@ rows, separated by a thin band. Use Zed's version-control colors (added #27a657, deleted #e06c76): a 3px gutter bar, a 10% line wash, and a stronger wash on changed words of similar replaced lines. Offer Unified and Split in the editor's 32px title row and remember the choice: Unified numbers lines by the new file, and Split places old beside new with blank filler for unmatched lines. Lines soft-wrap to the available width in both Unified and Split, preserving whitespace and changed-word highlights. Show original line numbers only on the first visual row; in Split, pad the shorter side with blank continuation rows to keep the next source lines aligned. Copy Zed's Git panel as a full-height 280px dock on the right, beside the editor rather than under its header, with its own 32px header (Changes, the file count and +/− totals), as the file tree has in Files. Below it: collapsible Tracked and Untracked sections with a count badge, each holding a folder tree with 1px indent guides, folders first, folder icons, and single-child folder chains on one row (`apps/desktop`). Files show a status square (modified dot #d3b020, added or untracked plus, deleted minus) and a foreground name, with +/− counts on tracked files. Clicking a file selects it, expands it if collapsed, and scrolls its header to the top of the multibuffer. Update automatically like Files, reloading only for working-tree changes and commits, without a Refresh button.
- Render `.md` and `.markdown` files as a native, selectable Markdown reading preview in the content area, with scrolling and comfortable padding. Keep automatic file updates and existing read limits; other text files use the read-only code editor. Leave the content area blank until a file is opened, without a selection prompt or a preview header.
- Open files as tabs above the content area, as Zed does: a 32px chrome tab bar with a bottom border, aligned with the file tree's title row. A single click (or Enter) in the tree shows the file in one reusable preview tab whose name is italic and one step dimmer than a kept tab's (muted when shown, dim otherwise), so it stays distinct in fonts without italics; double-clicking the file or its tab keeps it open, and new tabs open at the end of the bar; the preview tab is replaced where it stands. Each tab shows a file icon and the file name, adding its muted folder when two open files share a name; the shown tab uses the content background.
