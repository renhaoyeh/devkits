# Herdr

A native Herdr layout and GPUI mod with shadcn/ui Sera styling and a Zed-inspired project and thread sidebar.

Click the chart icon in **AGENT PROFILES** to open **Token statistics**. Choose Today, 7 days, 30 days or All time; inspect daily totals and Models, Projects, Accounts or Sessions. Click a daily bar or grouped row to filter, then Clear filters to reset. Tables show uncached input, output, cache reads, cache writes and their total; reasoning is already included in output. Statistics read local Codex/Claude transcripts (including Herdr account directories and archived Codex sessions), deduplicate repeated events, cache parsed files under `data/devkits/analytics-cache.json`, and refresh every minute while open. Dates use the computer's local timezone. Only recorded history can be counted; missing metadata is labeled unknown. Token totals include cache traffic and do not represent subscription charges. No provider requests or Orca installation are required.

## Install

Requires Herdr App and Node.js 22+. Run from the repository root:

```sh
npm run install:herdr
herdr-app check ~/.config/herdr-app/mods/devkits
herdr-app do layout.switch --name devkits
```

If `herdr-app` is not on PATH, use `~/.local/bin/herdr-app`.
The installer adds the custom layout, mod, and themes to `~/.config/herdr-app/` and refuses to overwrite existing files. For updates or a custom `HERDR_APP_HOME`, see [DEVELOPMENT.md](DEVELOPMENT.md).

## Use

The **Agent profiles** area below the threads list and above the sidebar settings footer stacks accounts vertically and follows **Add session → Manage…** visibility and ordering, including Terminal. Its settings icon button opens the existing profile management dialog for account, permissions, visibility, and ordering changes. Rows fit their content, with top-aligned text and vertically centered icons. Every visible entry keeps a meter track. Local Codex and Claude accounts show separate **5h** and **Week** used meters for the windows actually returned; a weekly-only account shows only **Week**. Each meter keeps its used percentage beside the reset time: countdowns use hours/minutes below a day and days/hours for longer waits, such as **Resets in 6d 21h** (updated every minute). An elapsed reset shows **Reset due** until fresh data arrives; missing reset times show a dash. The fill follows usage, turning amber at 70% and red at 90% (green below 70%). These colors also apply in account details. Other providers show **Not supported**. Unavailable quotas keep a gray track with an explanation. Click an entry for all quota windows, used and remaining percentages, reset times, the last update, or an error explanation. The details dialog uses the same relative reset countdowns for every quota window, updated every minute while open. Each Codex account's result is cached in Herdr's shared state for 5 minutes, so reloads, restarts, and visibility changes reuse it instead of querying again; a failed refresh keeps the last good windows and shows the error in details. Only visible local Codex launchers and Devkits Claude accounts are read. Codex uses a temporary stdio app-server that stops after the request. Claude usage never uses credentials or the network: when an account is added (or first shown, for older accounts), Devkits sets a status line in that account's own `settings.json`, unless one is already configured. Claude Code passes its plan usage (`rate_limits`) to that status line, which records it in `devkits-usage.json` in the account directory and shows `5h 13% · Week 32%` in Claude Code. The sidebar rereads this local file every minute, so it updates while you use the account and keeps the last recording, with its time, when you do not. Accounts show **No usage yet** until their first Claude session. The built-in Claude agent (`~/.claude`) is supported the same way. If it already has a command status line from another tool (such as Orca), Devkits saves it to `~/.claude/devkits-statusline-chain.json`, backs up `settings.json` once as `settings.json.devkits-backup`, and runs that command after recording with the same input, showing its output when it prints any. If the other tool restores its own status line later, Devkits chains it again the next time the sidebar starts. To undo, restore the backup. Remote usage is marked unsupported. Node.js must remain on PATH; no devkit CLI is required.

The quota meters also compare usage with time in two equal-height bands: the muted top half and its vertical marker show how much of the current window has elapsed, while the colored bottom half shows quota used. If the colored line extends past the marker, usage is ahead of an even pace across that window. Details show the elapsed percentage and explain the two halves. This measures the whole quota window rather than today's usage, and does not predict when quota will run out. Missing, inconsistent, or expired reset data hides the time band until fresh data arrives.

Click the project name at the top and choose **Open folder…**. Opening a folder does not start a session; use the project's **+** to choose an agent or terminal. Close a workspace through its **⋯** menu.

Click the folder icon at the right of the status bar to toggle project files. The file tree appears on the right; the read-only preview appears on the left. `.md` and `.markdown` files open as a rendered Markdown reading preview with selectable text and scrolling. Other text files use a code preview with syntax highlighting, line numbers, soft wrapping, selection, and copying. Soft wrapping fits long lines to the preview width without changing file contents. Use arrow keys and Enter in the tree; click the status bar folder icon again or select a session in the sidebar to return to terminals. Local filesystem changes automatically update the tree and current preview, preserving expanded folders and selection. Remote folders, or local folders where native watching is unavailable, update every 10 seconds. Listing uses `sh` on the project's machine (macOS/Linux); `.git` and special files are omitted. Lists are limited to 500 entries per folder and 5,000 total, previews to 400,000 characters, and reads to Herdr's 1 MiB limit. Binary and unreadable files show an explanation.

Choose **Add session → Manage…** to open a large dialog and show or hide Terminal and individual installed agents or accounts. Terminal, built-in agents, and **Your accounts** have separate sections in both the dialog and menu. Drag a handle to reorder within a section; leave the dialog or press Escape to cancel a drag. Alternatively, select a row and press Alt + Up/Down to reorder. Visibility and order are saved across projects and app restarts; hiding an entry does not remove its account or stop running sessions. New entries appear after the saved entries in their section, and number shortcuts follow the visible agent order. Click the backdrop, choose **Done**, or press Escape to close Manage.

For a local project, open **Add session → Manage…** and choose **+ Add account** on the **Codex** or **Claude** row. Name the account and continue with ChatGPT (Codex) or your Claude subscription (Claude Code) in your browser. Names accept 1–48 printable characters, including Chinese and uppercase letters. Completing or cancelling sign-in returns to Manage; a connected account appears as **Codex · name** or **Claude · name**, ready to show, hide, or reorder. It does not start a work session automatically.

The inline permissions Select on the Codex row and each custom Codex account sets that launcher's default for new sessions. It shows names without subtitles: **Default** (neutral), **Read only** (blue), **Workspace** (green), **Full access** (red), with explanations in tooltips. **Default** keeps its existing command and Codex configuration; **Read only** uses `--sandbox read-only --ask-for-approval on-request`; **Workspace** uses `--sandbox workspace-write --ask-for-approval on-request`; **Full access** uses `--sandbox danger-full-access --ask-for-approval never`, allowing commands outside the sandbox without approval. These flags follow the [official Codex CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli). The setting is saved per launcher, replaces conflicting permission flags, and does not change existing sessions, account credentials, other agents or Codex config files.

The **Claude** row and each Claude account have the same Select with Claude Code permission modes: **Default** (neutral) keeps the existing command and settings; **Plan** (blue) uses `--permission-mode plan`; **Accept edits** (green) uses `--permission-mode acceptEdits`; **Full access** (red) uses `--permission-mode bypassPermissions`, running commands without permission prompts. It is saved per launcher, replaces conflicting `--permission-mode` and `--dangerously-skip-permissions` flags, and applies only to new sessions.

Login runs inside the plugin using the official `codex app-server`, without a devkit CLI or wrapper. Each new account has a fixed, automatically allocated ID and its own `data/devkits/codex/<id>/` under Herdr's config directory. The display name is never used as a path or command argument; `Work` and `work` stay separate even on case-insensitive disks. Existing account entries retain their original paths, and the default `.codex` directory is not copied. Codex stores and refreshes its credentials. The temporary server listens only on a random localhost port and stops when login finishes, fails, times out, or the dialog closes. If adding the menu entry fails, retrying in the same dialog reuses the ID and credentials, even if the display name changes. Codex currently marks WebSocket transport as experimental.

Claude accounts sign in with the official `claude auth login --claudeai` in a temporary background terminal, using their own `data/devkits/claude/<id>/` as `CLAUDE_CONFIG_DIR` (and `CLAUDE_SECURESTORAGE_CONFIG_DIR`, so macOS Keychain entries are per account; Claude Code 2.1.144 or later). Claude Code opens the browser itself; if the browser shows an authentication code instead, paste it into the dialog. The account is added only after `claude auth status` confirms a Claude subscription login. Launchers and sign-in unset `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, and `CLAUDE_CODE_OAUTH_TOKEN` so inherited credentials cannot override the account. Each account has its own Claude settings, history, and onboarding state; the default `~/.claude` is not copied. Codex default permissions and usage meters are not available for Claude accounts.

Account entries are merged into `programs.json` with an atomic compare-and-swap. Existing entries are preserved; duplicate labels and concurrent settings changes are not overwritten. These local account entries are hidden from remote project menus.

On a row in **Your accounts**, choose **Remove** and confirm to run `codex logout` or `claude auth logout` against that account's dedicated Devkits directory, then remove its menu entry and saved visibility/order preferences. History and project files are kept. Running sessions are not closed, but may require sign-in again. Built-in agents cannot be removed this way. External or shared credential directories are rejected. Logout failures keep the entry; if logout succeeds but settings cannot be updated, the dialog explains the partial result and allows a retry.

To return to Herdr's default layout:

```sh
herdr-app do layout.switch --name main
```

## Asana tasks

In a local project's **…** menu, choose **Asana tasks**. The first time, paste a personal access token from the [Asana developer console](https://app.asana.com/0/my-apps) (saved in `~/.config/herdr-app/data/devkits/asana.json`) and choose the Asana project for this Devkits project; click the project name in the toolbar to switch it later. Switch between **List** and **Board** (grouped by the project's sections) and between **All** and **Saved**. Select a task to preview its description and subtasks, then decide: **Save for later** bookmarks it under **Saved** on this computer only (finished or deleted tasks drop off automatically), and **Start session** picks an agent and starts it with the task's name, link, parent task and description as the prompt. Devkits only reads Asana and never changes it.
