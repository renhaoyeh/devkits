# Herdr

A native Herdr layout and GPUI mod with shadcn/ui Sera styling and a Zed-inspired project and thread sidebar.

The bottom status bar keeps conversation and metrics on the left. Its right side groups **System / Calendar / Tasks**, followed by the **Simulator / Changes / Files** panel icons. The gear before these groups opens Herdr settings. Controls share full-height targets and selected states; the action strip scrolls horizontally in narrow windows.

Open **Calendar** from the calendar icon beside Tasks in the bottom status bar. It is a local calendar with the same Linear styling as Tasks. Switch between **Day**, **Week** and **Month**; the chosen view is remembered. Day and Week show events along a scrollable 24-hour timeline, with all-day events above and overlapping events side by side. Use Today and the arrows to navigate a day, week or month according to the active view. In Month, clicking a date selects it for the right-hand agenda without moving the month grid, including dates from neighbouring months; choose Day to inspect that selected date's timeline. **New event** opens a separate creation dialog on the selected date. You can also drag a blank Day/Week timeline to select a time range (snapped to 15 minutes), or drag across Month dates/the all-day row to select an all-day range. Release to open the dialog with those dates and times filled in. The selected range remains highlighted behind the dialog until the event is created or the dialog is dismissed; validation errors keep the preview visible. While still dragging, Escape or leaving the grid cancels the selection. Enter a title, start/end dates (`YYYY-MM-DD`), times (`HH:MM`, 24-hour), or choose **All day**, and add optional notes. All-day ranges include the end date. New events default to **New event**, so you can click **Create event** immediately and rename them later. You can also change the title before saving. If you manually clear the title, the required-title hint and focus validation still apply. Existing events open in the right-side editor for edits or deletion. **Cancel** discards edits. Closing a creation dialog returns to the existing Calendar and preserves any pending inline edit. Escape cancels an active selection first, closes a creation dialog, or cancels the inline editor before closing Calendar; Cmd/Ctrl+Enter saves the active dialog/editor.

Type **@** in the title or notes to search existing Tasks by task or project name. The picker opens directly below the typed @, including on later lines. Choose a result with the mouse or Arrow keys and Enter; Escape closes only the picker. Task references appear as inline labels and are saved with the event. Click a reference in an existing event to open its project’s Tasks detail. New selections omit archived tasks; existing links still open archived tasks. A removed task keeps its saved label and shows an unavailable message when clicked. Linking a task does not run it.

Committed events are saved in Herdr's local shared storage and survive reloads and restarts. Timed events use this computer's time zone. No account connection is required. The calendar is independent of project selection and does not automatically start tasks or agents.

SYSTEM runs in its own `devkits-system` mod; Devkits consumes its snapshot/rendering SDK and controls placement through the right-click menu. Asana and MantisBT are separate `devkits-asana` and `devkits-mantisbt` mods. They own their connections and source browsers; Devkits receives import snapshots and owns Tasks drafts and execution. Existing connections and preferences are retained.

Configure the monitor through the **System** action in the bottom status bar, independently of Agent settings. Right-click the Devkits sidebar or bottom status bar to toggle **Show in sidebar** and **Show in status bar** independently. The same menu chooses the sidebar’s **Inline values**, **Compact widgets** or **History widgets**, and its widget CPU **Total / Per core** view. Inline values reuses the bottom bar’s compact percentages and transfer speeds inside the sidebar; each metric opens its details. Both locations can be shown together. These display choices belong to Devkits, separately from SYSTEM monitoring settings. In Sidebar mode, drag the monitor’s top border to adjust its height; double-click to reset. The height is remembered, and widgets scroll within it. Choose CPU, GPU, RAM, Disk activity, Network, Storage, Battery and Sensors independently, drag the same grip handles used in Agents/Models to reorder widgets (or focus a handle and use Alt+Up/Down), and refresh every 1/3/5/10 seconds. Widget style and placement are controlled through Devkits’ right-click menu. Choices survive restarts, including when all widgets are hidden. Battery appears only when detected and selected; Storage and Sensors start unchecked. RAM and Disk show total capacity at the right of the sidebar title, with used memory/percentage and disk **R/W** below. Disk also names the system volume’s physical drive model; its full model/type/connection appear in details when reported. RAM includes the OS-reported DDR/LPDDR type, with manufacturer and reported speed in details. GPU shows the busiest adapter’s memory capacity and names its unified/shared pool or dedicated VRAM; Apple unified memory is the same system memory pool, not additional VRAM. Windows reads 64-bit DXGI capacities and joins performance counters by adapter identity instead of using the 32-bit AdapterRAM property. Common hardware readings use the bundled **systeminformation 5.33.19** package, including RAM/layout, CPU metadata, disk models/capacity, network counters and battery. Its upstream code and MIT license ship inside the mod, so installation needs no global npm package or runtime download. Static inventory is cached for five minutes. Native supplements cover the package’s missing P/E logical identities, Apple GPU utilization, precise Windows GPU identities/64-bit capacities, physical disk I/O, RAM breakdown/pressure, battery temperature and optional sensors. The monitor uses 90% of the window width, with a three-column Overview (two in narrower windows), charts/metadata side by side and two-column Settings. CPU has Task Manager-style **Total**, **Logical processors** and **P/E groups** views with individual histories and selectable processors. Physical cores, logical processors and sockets are separate; SMT siblings remain distinct. P/E labels come from OS topology, never core-number guesses. CPU selection changes only what is displayed. Close with Done, Escape or the backdrop. Live readings and bounded three-minute histories stay in session memory; only preferences persist.

Both platforms read common information through systeminformation. The macOS supplement maps actual IODeviceTree CPU IDs to P/E types and adds missing GPU/sensor/detail readings. The Windows supplement uses local CPU/disk/GPU performance counters and GetSystemCpuSetInformation for processor groups/core types; counters use elapsed deltas and preserve raw 64-bit CPU timer precision. Missing providers leave their own fields unavailable. Optional **Sensors** shows CPU/GPU/SSD temperatures, fans and power with sources and units. CPU/GPU summaries are the highest returned thermal sensor, not per-core temperatures or battery temperature. The bundled macOS SMC reader uses existing Apple Command Line Tools for a cached local build; it never starts an installer or asks for root. Key coverage currently includes Intel and Apple M1–M4 families; unsupported readings remain unavailable. Windows sensor coverage depends on drivers: use available NVIDIA query endpoints or an already-running LibreHardwareMonitor WMI provider, without installing/starting either. NVIDIA fan percentages remain labeled **%**, not RPM. Monitoring never changes scheduling/affinity, resource limits, power settings or fan modes. It adds sampling overhead; sensors are opt-in. Module presentation follows [Stats](https://github.com/exelban/stats/tree/master/Modules); SMC ABI/key attribution is bundled in `assets/licenses/stats.txt`.

Click the chart icon in **USAGE** to open **Token statistics**. Switch between All, Codex and Claude to filter totals, estimated cost, daily bars and every table together. Choose Today, 7 days, 30 days or All time; inspect daily totals and Models, Projects, Accounts or Sessions. Click a daily bar or grouped row to filter, then Clear filters to reset, including the provider. Changing providers clears model and account filters while keeping the date range and day/project filters. Tables show uncached input, output, cache reads, cache writes and their total; reasoning is already included in output. Statistics read local Codex/Claude transcripts (including Herdr account directories and archived Codex sessions), deduplicate repeated events, cache parsed files under `data/devkits/analytics-cache.json`, and refresh every minute while open. Dates use the computer's local timezone. Only recorded history can be counted; missing metadata is labeled unknown. Token totals include cache traffic and do not represent subscription charges. No provider requests or Orca installation are required.

Token statistics shows **Est. cost · USD** in the fixed top summary alongside token totals, and **Est. USD** in each grouping, using bundled standard API rates checked on 2026-11-06 ([OpenAI](https://developers.openai.com/api/docs/pricing), [Claude](https://platform.claude.com/docs/en/about-claude/pricing); individual legacy OpenAI model sources are listed in `analytics-pricing.js`). The estimate follows the active range and filters. It is API equivalent token cost, not subscription charges or a historical invoice: long-context, speed, regional, tool and tax adjustments are excluded. Cache writes assume short TTL unless Claude records one-hour writes. Unknown models leave the amount blank; mixed groups show the known numeric subtotal without pricing-status labels. New model IDs need a verified entry in the bundled rate table; no runtime pricing requests are made.

## Install

Tell your agent:

```text
Read ~/.config/herdr-app/AGENTS.md, then add this layout: https://github.com/renhaoyeh/devkits/tree/main/herdr
```

The [recipe](RECIPE.md) describes the layout, its companion mods and themes, installation, and validation. Your agent reads the files before adding it alongside your existing layouts. If you use a custom `HERDR_APP_HOME`, point the agent at that directory's `AGENTS.md` instead.

For manual installation, clone this repository and run the commands below.

Requires Herdr App and Node.js 22+. Run from the repository root:

On Windows, keep Node.js and Git for Windows on Herdr's PATH. Account directories are created with Node's filesystem API; account launchers, usage reads, and settings synchronization use Git's bundled shell for Unix-style environment commands and npm launchers. WSL is not required. Existing `env` account launchers remain supported.

```sh
npm run install:herdr
herdr-app check ~/.config/herdr-app/mods/devkits
herdr-app check ~/.config/herdr-app/mods/devkits-system
herdr-app check ~/.config/herdr-app/mods/devkits-asana
herdr-app check ~/.config/herdr-app/mods/devkits-mantisbt
herdr-app check ~/.config/herdr-app/mods/devkits-simulator
herdr-app check ~/.config/herdr-app/mods/devkits-sim-frames
herdr-app do layout.switch --name devkits
```

If `herdr-app` is not on PATH, use `~/.local/bin/herdr-app`.
The installer adds the custom layout, mods, and themes to `~/.config/herdr-app/` and refuses to overwrite existing files. For updates or a custom `HERDR_APP_HOME`, see [DEVELOPMENT.md](DEVELOPMENT.md).

## Use

Use **Add session → Settings → Usage → Show Usage in sidebar** to show or hide the entire USAGE section. It starts enabled. Turning it off pauses further quota refreshes and retains account selections, ordering and cached readings; turn it back on from the same settings page. This does not change which accounts are available for Agent profiles.

The **Usage** area below the threads list and above the sidebar settings footer stacks accounts vertically and follows **Add session → Settings…** visibility and ordering, including Terminal. The refresh icon rediscovers profiles and rereads visible account usage immediately, bypassing the Codex cache; it is disabled while usage is loading. Rows fit their content, with top-aligned text and vertically centered icons. Every visible entry keeps a meter track. Local Codex launchers, Devkits Claude accounts and the built-in Claude profile show separate **5h** and **Week** used meters for the windows actually returned; a weekly-only account shows only **Week**. Each meter keeps its used percentage beside the reset time: countdowns use hours/minutes below a day and days/hours for longer waits, such as **Resets in 6d 21h** (updated every minute). An elapsed reset shows **Reset due** until fresh data arrives; missing reset times show a dash. The fill follows usage, turning amber at 70% and red at 90% (green below 70%). These colors also apply in account details. Other providers show **Not supported**. Unavailable quotas keep a gray track with an explanation. Click an entry for all quota windows, used and remaining percentages, reset times, the last update, or an error explanation. The details dialog uses the same relative reset countdowns for every quota window, updated every minute while open; click the backdrop, choose **Done**, or press Escape to close it. Remote usage is marked unsupported.

Each Codex account's result is cached in Herdr's shared state for 5 minutes, so reloads, restarts, and visibility changes reuse it instead of querying again; a failed refresh keeps the last good windows and shows the error in details. Only visible supported local profiles are read. Codex uses a temporary stdio app-server that stops after the request.

Claude usage never uses credentials or the network: when an account is added (or first shown, for older accounts), Devkits sets a status line in that account's own `settings.json`, unless one is already configured. Claude Code passes its plan usage (`rate_limits`) to that status line, which records it in `devkits-usage.json` in the account directory and shows `5h 13% · Week 32%` in Claude Code. The sidebar rereads this local file every minute, so it updates while you use the account and keeps the last recording, with its time, when you do not. Accounts show **No usage yet** until usage has been recorded. The built-in Claude agent (`~/.claude`) is supported the same way. If it already has a command status line from another tool (such as Orca), Devkits saves it to `~/.claude/devkits-statusline-chain.json`, backs up `settings.json` once as `settings.json.devkits-backup`, and runs that command after recording with the same input, showing its output when it prints any. If the other tool restores its own status line later, Devkits chains it again the next time the sidebar starts. To undo, restore the backup. Node.js must remain on PATH; no devkit CLI is required.

The quota meters also compare usage with time in two equal-height bands: the muted top half and its vertical marker show how much of the current window has elapsed, while the colored bottom half shows quota used. If the colored line extends past the marker, usage is ahead of an even pace across that window. Details show the elapsed percentage and explain the two halves. This measures the whole quota window rather than today's usage, and does not predict when quota will run out. Missing, inconsistent, or expired reset data hides the time band until fresh data arrives.

Click the project name at the top and choose **Open folder…**. Use **+** on the thread title bar to open Add session for that thread’s project. Press **⌘W** to close the active central file tab, even with the right dock closed or showing Git; with central diff content or no file it does nothing. Press **⌘N** to start a thread with this project’s last used agent profile and its current defaults. The remembered agent shows its New thread shortcut at the right of its Add session row. New projects use the globally last used agent, or the first available visible agent; Add session opens only when none is available; plain terminal sessions do not change the remembered agent. New projects start with the central editor and Files dock visible; the conversation area and Simulator are hidden. Use the Agent sparkle icon on the left of the bottom status bar to show or hide the conversation. Hidden sessions keep running. The conversation header’s **⋯** menu contains only **Close thread**, including for an accidentally created empty session. Selecting a thread or starting a session shows the conversation; each project remembers its visibility. Opening a folder creates a hidden default terminal to keep the project open; use the project's **+** to start a thread with that project’s last used agent (new projects inherit the global default). Reopening an existing project selects it without creating another default terminal. Ordinary terminal rows and pane headers show a rotating icon while a foreground command runs, then restore the program or terminal icon when it returns to the shell. Agent reports take precedence; shell builtins and detached jobs are not tracked. Terminals an agent starts with `hc run` (a dev server, a simulator) appear indented under its thread while they run; click one to peek at it over the thread, or hover it and click its close button to end it. Hover a running or waiting local Claude or Codex thread and click Stop to interrupt generation while keeping its session open. Once inactive, click its archive icon to end the session and keep its conversation in the archive (a session without a conversation yet simply closes). Threads opened as Terminal keep their Close button even when Codex or Claude is run inside the shell, including after Herdr restarts. On Windows, macOS and Linux, inactive agent threads use the same background check before Archive becomes available; if no resumable conversation can be identified, the row shows Close directly, including for empty sessions. Codex archiving currently requires an open rollout file; if it becomes unavailable after the check, the archive attempt keeps the thread running and changes its action to Close. Clicking Close then ends the session without adding an archive entry. Terminals and other threads show a close button instead. Click the clock icon at the bottom of the sidebar to switch between threads and archived threads; click an archived thread to resume it (`claude --resume` or `codex resume`, with the same account and flags) in its project, or hover it and remove it from the archive. Removing never deletes transcripts. Close a project through its **⋯** menu. Use **Move up** and **Move down** there to reorder projects; the order is saved immediately. Tasks stays open across project switches; selecting a conversation returns to the terminal workspace.

As in Zed, the header shows the current branch beside the project name; click it to see the project's local and remote branches, most recently committed first (switching branches is not available yet). The left of the status bar names the machine of a remote project.

Click the folder icon at the right of the status bar to show or hide project files beside the thread, as in Zed: the read-only preview appears next to the thread with the file tree at its right, and the iOS Simulator panel, when shown, stays at the window's edge. Drag the divider between the thread and the preview to resize them, and the line between the preview and the file tree to resize the tree (Changes shares that width); Files stays open while you switch threads. Each project remembers its own Files/Changes visibility and selection, editor size, Simulator visibility and width, Files/Changes list width and Asana preview width across project switches and restarts; new projects start with the Files dock open and Simulator closed. `.md` and `.markdown` files open as a rendered Markdown reading preview with selectable text and scrolling. Other text files use a code preview with syntax highlighting, line numbers, soft wrapping, selection, and copying. Soft wrapping fits long lines to the preview width without changing file contents. Use arrow keys and Enter in the tree; click the status bar folder icon again to hide only the file tree; the current document stays visible. Local filesystem changes automatically update the tree and current preview, preserving expanded folders and selection. Remote folders, or local folders where native watching is unavailable, update every 10 seconds. Listing and Git operations use `sh` on the project's machine; when it is unavailable, they use Git's shell (including Git for Windows) without changing PATH or saved Git configuration; `.git` and special files are omitted. Lists are limited to 500 entries per folder and 5,000 total, previews to 400,000 characters, and reads to Herdr's 1 MiB limit. Binary and unreadable files show an explanation.

Right-click a file or folder in Files for **Copy Relative Path**, **Copy Full Path**, or **Reveal in File Explorer** (Finder on macOS). Relative paths start at the project folder; full Windows paths use native backslashes. Reveal selects the item on Windows/macOS and opens its containing folder on Linux. Remote projects support copying paths, with Reveal disabled. Ignored files and folders remain visible in a dim color.

Files open in tabs above the preview. Single-click a file (or press Enter) to reuse the italic, dimmer preview tab; double-click the file or its tab to keep it open. Close a tab with its close button or the middle mouse button. When open files share a name, their tabs also show the folder. **⋯ Tab options → Wrap tabs** switches between one horizontally scrolling row and multiple rows; the choice is remembered across projects and restarts. Each project remembers its open tabs, selected tab and preview tab across reloads and restarts. Background tabs retain their scroll position and reread changed files when selected.

Click the phone icon in the status bar to show or hide the **iOS Simulator** panel on the right of the workspace; drag its left edge to resize it. Choose a simulator from the picker in its header; a shut-down simulator boots when chosen, and the first booted one is shown by default. Click the screen to tap, drag to swipe, scroll with the mouse or trackpad, and type after clicking the screen. The toolbar presses Home, Lock and the volume keys, rotates the device, and shows or hides the software keyboard. The panel's picture lags about 0.2 seconds because Herdr can only show frames as image files; for smooth interaction, click the open-in-window icon in the panel header to open the same device in serve-sim's 60 FPS preview, in a Chrome app window (or the default browser). That window stops when the panel's own serve-sim helper stops, for example when switching devices. If taps stop working on Xcode 27, choose **Repair input** in the picker (it restarts SpringBoard and closes apps). On Windows and Linux the panel opens but says the simulator is not supported. The panel needs macOS with Xcode and an iOS simulator, an Apple Silicon Mac and Node.js 20+; it runs [serve-sim](https://github.com/EvanBacon/serve-sim) locally through `npx` (downloaded from npm the first time) and streams only while the panel is shown. The panel is its own mod, `devkits-simulator`; a layout without the `simulator` block leaves it out, along with its status bar icon. Frames are written to `mods/devkits-sim-frames/`. Adapted from [herdr-sim](https://github.com/wobsoriano/herdr-sim).

The header's run button runs the shown project's chosen command, like F5 in an editor; press **F5** for the same. Choose the command from the arrow beside it: one of the project's `package.json` scripts through its package manager (for example `bun run dev` or `bun run iphone`), or a custom command typed into the menu and confirmed with Enter. The chosen command shows on the button and leads the menu; each project keeps its own, on this computer only. `{udid}` in a command stands for the simulator chosen in the simulator panel, else the first booted one (for example `bun expo run:ios --device {udid}`); commands without it never touch the simulator. The command runs in a project thread named after the actual command (for example **bun run ios**), shown in both the sidebar and title bar, in a login shell that stays open afterwards. Running again closes the previous run thread (and its dev server) first, even when the chosen command changes. The installer binds F5 in the Devkits layout unless that key is already bound there (`"layout:devkits": { "f5": "devkits.run" }` in `keys.json`).

The device picker lists recently used simulators first and never-used devices last, showing their iOS version and relative last use. Use the power button beside a booted device to shut it down. While another client, such as the separate preview window, is connected to the helper, the panel pauses its own stream and shows **Showing in the preview window**; close that client to resume the panel stream.

Choose **Xcode storage…** at the bottom of the device picker to inspect DerivedData, simulators, runtimes and archives. DerivedData is grouped by project, and simulators by recent use. DerivedData whose workspace is missing starts selected on the first scan. Select the items to remove, then choose **Delete…** and confirm the count and size. Only selected DerivedData folders and shut-down simulators can be deleted; booted devices cannot be selected. Runtimes and archives are size-only entries managed through Xcode. Nothing is deleted automatically.

Click the compare icon beside Files to show the **Git** dock in the right column. View Diff, a changed file, or a commit opens its diff in the central editor. Switching between Files and Git, or closing either dock, preserves the current central content. Double-click the dock divider to reset its width. Unified and Split diffs soft-wrap long lines to the available column width, keeping original line numbers and changed-word highlights. Split rows stay aligned when one side wraps onto more lines. Changes shows its file list and count as soon as metadata arrives, then loads patches one file at a time, yielding while parsing and keeping the previous diff during refreshes or read errors. Both the editor and the file list render only visible rows. The preview keeps its 4 MB / 10,000-row safety limits; select a deferred file in the Changes list to prioritize loading its contents. Hidden lockfile contents are not loaded. Commit patches are capped before being transferred to the UI.

Open **Git Graph** with the graph icon beside the latest commit at the bottom of **Changes**, below the Git action footer. Clicking that commit’s subject opens its commit tab. It opens a Zed-style central table with colored branch and merge lines, branch/tag labels, description, date, author and commit ID. Drag column boundaries to resize them and right-click the table header to choose visible columns. Search messages, authors or commit IDs across all local history, with **Aa** for case sensitivity and arrows to move between matches. Click a commit for its details and changed files; double-click, press Enter or choose **View Commit** for its diff, then select the **Git Graph** tab to return. Files, Git Graph and each commit share the same tab strip; opening a commit keeps your file and graph tabs available. In the commit diff, the description starts folded to its subject; use the disclosure beside the author to expand or fold a multiline message. The details file list switches between tree and flat views and follows **Hide lock files**. Right-click a commit to view its changes or copy its SHA/message. History loads automatically as you scroll, from fixed snapshots of local refs; it never fetches automatically.

The right Git panel's footer shows the current branch and a solid split button that follows Zed: **Fetch** when synchronized, **↑N Push** when only ahead, and **↓N Pull** whenever behind (including **↓N ↑N Pull** when diverged). Without an upstream it shows **Publish**; if the configured upstream ref is gone, **Republish**. Zero counts are hidden. Counts use local tracking refs and update after commits, fetches and Git operations; remote changes become known after Fetch, with no automatic fetching. **Fetch** runs `git fetch --all` without merging. Click the separate arrow for **Fetch**, **Fetch From…**, **Pull**, **Pull (Rebase)**, **Push**, **Push To…** and **Force Push (with lease)**. Fetch From lists existing remotes and **All** when there are several. Publish and Republish push the current branch and set its upstream; Push and Push To also publish when needed. Publishing uses the configured push remote, origin or the sole remote, or asks you to choose when there is no default. Tracked pushes and pulls retain Git's configuration, and Force Push uses `--force-with-lease`. Operations show progress plus success or failure feedback; authentication and rejected operations display Git's error for retry. Actions are disabled while another operation runs; Fetch remains available before the first commit and on detached HEAD if a remote exists. The menu supports arrow keys, Enter, Escape and outside-click dismissal.

Choose **GitHub account** from the Git action menu to select an account already signed in with `gh auth login` on the project's machine. The choice is remembered per machine and project folder and applies to Fetch, Pull, Push and publishing. **Default** uses your existing Git authentication; **Refresh accounts** rereads the signed-in accounts, and unavailable accounts require signing in again. Selecting an account does not switch gh's global active account. Operations use HTTPS for that account's host, including conventional `git@host:…` and `ssh://git@host/…` remotes, without changing the saved remote URL. Other hosts keep their own authentication.

Loading appears in the center of Changes while the Git footer keeps its height and shows a branch placeholder until ready.

In the right **Changes** panel, the compact toolbar shows a static **View Diff** title and added/removed totals on the left. Click the **sliders icon on its right → List / Tree** to switch between flat project-relative paths and nested folders. Tree is the default; the choice is remembered across projects and restarts. Both views retain Tracked and Untracked sections, lockfile filtering, status colors and change counts. Switching preserves the selected file and diff scroll position. The editor's **⋯ Diff options** menu keeps Wrap and Hide lock files.

Choose **History** in the right Git panel to browse commits reachable from the current HEAD. Each row shows the message subject, author, short SHA and time. Scrolling to the end or navigating near it with the keyboard automatically loads the next 50 commits, without a Load more button; each batch uses the same revision even if a new commit arrives. Click a commit (or use arrow keys and Enter) to inspect its full message and unified/split diff on the left. Root commits show all their files; merge commits show changes against their first parent. Switch back to **Changes** for the working diff. History refreshes after HEAD changes, retains the current result during reads, and uses local Git without fetching or contacting a hosting service.

Open Herdr’s app settings from the gear at the left edge of the bottom-right status bar controls. Choose **Add session → Settings…** to open **Settings**, the one place for Devkits settings, with its pages listed on the left. Its **Agents** page shows or hides Terminal and individual installed agents or accounts. Terminal, built-in agents, and **Your accounts** have separate sections in both the dialog and menu. Drag a handle to reorder within a section; leave the dialog or press Escape to cancel a drag. Alternatively, select a row and press Alt + Up/Down to reorder. Visibility and order are saved across projects and app restarts; hiding an entry does not remove its account or stop running sessions. New entries appear after the saved entries in their section, and number shortcuts follow the visible agent order. Click the backdrop, choose **Done**, or press Escape to close Settings.

Open the **Rules** page of **Settings** to read the global rules, `data/devkits/AGENTS.md` under Herdr's home, (read only; edit the file in any editor and the page follows). Like Zed's default rules, its contents are added to the system prompt of every Claude and Codex session started on this computer, for every account: Claude through `--append-system-prompt-file`, Codex through `-c developer_instructions=…` (which replaces a `developer_instructions` set in that account's `config.toml`). Devkits writes starting rules once, asking agents to start long-running programs with `hc run --bg --name …` so they appear under their thread; edit or empty the file freely; it is never overwritten. Changes apply to sessions started afterwards; remote machines do not use it.

For a local project, open **Add session → Settings…** and, on the **Agents** page, choose **Add account** on the **Codex** or **Claude** row. Name the account and continue with ChatGPT (Codex) or your Claude subscription (Claude Code) in your browser. Names accept 1–48 printable characters, including Chinese and uppercase letters. Completing or cancelling sign-in returns to Settings; a connected account appears by its name with its provider icon, ready to show, hide, or reorder. It does not start a work session automatically. Its row's **⋯** menu contains **Rename**, **Shared plugins and skills…** (local Devkits Codex accounts only), and **Remove**. Renaming changes the display label without moving credentials or changing which account runs.

Open **Settings → Claude** or **Settings → Codex** to edit an account's defaults for ordinary sessions: **Permissions**, **Model**, **Effort**, and a Codex **Fast mode** checkbox. Native launchers and accounts remain managed on **Agents**. **Default** keeps the underlying launcher configuration. Codex models and supported efforts come from that account's local cache; changing Model clears an incompatible Effort and retains Fast mode. The provider-wide **Models and effort** section stays at the bottom of each provider page.

For optional reusable model setups, open **Agent profiles**, the final Settings page. Its table lists **Name**, **Account**, **Model**, **Effort** and **Speed**, with **Edit**/**Remove** actions. Created profiles are immediately available in Add session and Tasks, without a separate visibility or activation checkbox; old hidden flags for custom profiles are cleared. Click **Add** to open a creation form, enter a name, choose an account and configure its settings, then **Create**. No account selection is required before Add, and no profile exists until Create. **Edit** uses the same form with **Save**. Add/Edit forms stack above the existing Settings table. Save, Cancel and Escape close only the top form, preserving the table and its scroll position; Cancel and Escape discard changes. New profiles offer only accounts checked in **Settings → Usage**, in the same section and saved order. Create rechecks that selection; Add is disabled when no eligible account is checked. Existing profiles remain listed, and editing can retain their original account even after it is unchecked; alternative accounts must be checked in Usage. Native Default agents never appear as custom records. Each profile reuses its account's credentials and executable while retaining independent settings. Add session lists custom profiles as **Profile name - Account name** in its own final **Agent profiles** section; **Tasks** and **⌘N** also support them. Existing profiles remain available. Removing a profile leaves running sessions and conversation history intact. All account and agent menus share one label-and-icon rule: provider icons identify Codex/Claude, account name prefixes are removed regardless of letter case, and a bare provider label is displayed as **Default account**. Stored names, IDs, credentials and commands stay unchanged.

Tasks' **Default** option names the selected launcher's inherited value; explicit session choices override it. Provider model and effort availability applies to both native defaults and custom profiles. Hiding an item clears matching defaults. Changes affect new sessions.

At the bottom of an Agent profile's Add/Edit form, **Additional system instructions** accepts optional multiline instructions. Create/Save stores them independently for that profile; Cancel/Escape discards edits. New local sessions append them after global Rules, including sessions started through Tasks or **⌘N**. Leave the field blank to use global Rules alone. The global rules file is never modified, and profile instructions still apply if it is empty, missing or unreadable. Claude uses `--append-system-prompt` for the combined text; Codex uses one `developer_instructions` value. Changes apply to newly started sessions.

Open **Settings → Usage** to choose which account Profiles appear in the sidebar’s usage area and can be used to add Agent profiles, separately from native Add session visibility. Each Profile appears once even when several Agent configurations use it. Existing visibility is preserved initially; future Usage checkbox changes are independent of the Agents page.

For Codex accounts, **Permissions** offers **Default**, **Read only**, **Workspace** and **Full access**. **Default** keeps its existing command and Codex configuration; **Read only** uses `--sandbox read-only --ask-for-approval on-request`; **Workspace** uses `--sandbox workspace-write --ask-for-approval on-request`; **Full access** uses `--sandbox danger-full-access --ask-for-approval never`, allowing commands outside the sandbox without approval. The setting is saved per launcher and replaces conflicting permission flags without changing account credentials or Codex config files.

Claude accounts offer Claude Code permission modes: **Default** keeps the existing command and settings; **Plan** uses `--permission-mode plan`; **Accept edits** uses `--permission-mode acceptEdits`; **Full access** uses `--permission-mode bypassPermissions`, running commands without permission prompts. It is saved per launcher, replaces conflicting `--permission-mode` and `--dangerously-skip-permissions` flags, and applies only to new sessions.

Login runs inside the plugin using the official `codex app-server`, without a devkit CLI or wrapper. Each new account has a fixed, automatically allocated ID and its own `data/devkits/codex/<id>/` under Herdr's config directory. The display name is never used as a path or command argument; `Work` and `work` stay separate even on case-insensitive disks. Existing account entries retain their original paths, and the default `.codex` directory is not copied. Codex stores and refreshes its credentials. The temporary server listens only on a random localhost port and stops when login finishes, fails, times out, or the dialog closes. If adding the menu entry fails, retrying in the same dialog reuses the ID and credentials, even if the display name changes. Codex currently marks WebSocket transport as experimental.

Codex account sessions start directly with their existing plugins; startup never synchronizes or waits for shared settings. On the **Agents** page of **Settings**, open a saved local Codex account's **⋯ → Shared plugins and skills…** to choose individual local/Git marketplace plugins and legacy custom skills from `~/.codex`. Previously shared items are checked; new items start unchecked. The table has aligned **Name**, **Source** and **Status** columns; the header checkbox selects or clears all available plugins and skills. Opening this dialog shows **Checking shared settings…**, then checks actual links and profile configuration and labels each item **Synced**, **Update needed**, **Conflict**, **Not shared**, or **Source missing**. Checkboxes represent the desired sharing selection; status represents the checked state on disk. Checking does not apply changes. Click **Sync N items** to apply the selection. Devkits symlinks each selected plugin folder (not the entire marketplace) and selected legacy custom skills, and copies only corresponding marketplace/plugin settings through Codex's version-checked config API. Unchecking removes previously imported settings and Devkits-owned links, preserving source files and private profile data. Source folder changes are visible through the links; adding plugins or changing enablement requires another explicit sync, then a new session. Personal skills in `~/.agents/skills` already work across accounts. Remote account/workspace plugins still need installation and service authorization per account; remote caches, plugin data, system skills, credentials, conversations and temporary files remain independent. Conflicting real folders or foreign links stop synchronization without being overwritten. `devkits-shared.json` records imported settings/links and `config.toml.devkits-backup` preserves original settings before the first config change. Node.js and Codex CLI with the config read/batch-write API must be on PATH. Errors stay in the selection dialog; success returns to Settings with a notification. Existing sessions are not reloaded. While Devkits is open, global user skills in `~/.agents/skills` and legacy `~/.codex/skills` are monitored for additions, removals and content edits. Changes produce a notification; synchronization stays manual. Native file events are coalesced, with a 30-second snapshot fallback for missing directories and symlink targets. The sharing dialog watches the source skills and plugins folders and refreshes after a one-second burst of native file events, retaining your checkbox choices; new items remain unchecked. A 30-second fallback covers missing folders, linked targets and settings changes outside those folders.

Claude accounts sign in with the official `claude auth login --claudeai` in a temporary background terminal, using their own `data/devkits/claude/<id>/` as `CLAUDE_CONFIG_DIR` (and `CLAUDE_SECURESTORAGE_CONFIG_DIR`, so macOS Keychain entries are per account; Claude Code 2.1.144 or later). Claude Code opens the browser itself; if the browser shows an authentication code instead, paste it into the dialog. The account is added only after `claude auth status` confirms a Claude subscription login. Launchers and sign-in unset `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, and `CLAUDE_CODE_OAUTH_TOKEN` so inherited credentials cannot override the account. Each account has its own Claude settings, history, and onboarding state; the default `~/.claude` is not copied. Claude profiles have their own permission modes and support usage meters through the local status line recording described above.

Account entries are merged into `programs.json` with an atomic compare-and-swap. Existing entries are preserved; duplicate labels and concurrent settings changes are not overwritten. These local account entries are hidden from remote project menus.

On a row in **Your accounts**, open **⋯ → Remove** and confirm to run `codex logout` or `claude auth logout` against that account's dedicated Devkits directory, then remove its menu entry and saved visibility/order preferences. History and project files are kept. Running sessions are not closed, but may require sign-in again. Built-in agents cannot be removed this way. External or shared credential directories are rejected. Logout failures keep the entry; if logout succeeds but settings cannot be updated, the dialog explains the partial result and allows a retry.

To return to Herdr's default layout:

```sh
herdr-app do layout.switch --name main
```

## Tasks, Asana and MantisBT import

Open **Tasks** beside Calendar in the bottom status bar. Use **New task** for a manual task, or **Import from Asana** to pick an Asana source. Open **Settings** inside Asana to save, replace or clear a token; **Back to tasks** or **Cancel** returns without saving. The first time, paste a personal access token from the [Asana developer console](https://app.asana.com/0/my-apps) (saved under Herdr's home in `data/devkits/asana.json`) and choose the Asana project for this Devkits project from the searchable project dropdown in the toolbar. Each Devkits project remembers its binding. Tasks open in a modal pop-out with Asana-style project tabs, a task table and rounded board cards. Close it from its header; the background workspace is blocked while it is open. Switching projects keeps the pop-out bound to its original project. Choosing **Import into Tasks** closes the source browser and opens a task draft. Devkits only reads Asana and never changes it.

Switch between **List** and **Board**, grouped in Asana's section order, and between **Mine** and **All**; the view choices are remembered. Mine is the default and shows open tasks assigned to the token owner in this project. All loads 100 tasks at a time; use **Load more** to fetch another page. Search filters the loaded tasks. In List, click a task's subtask count to expand its sub-issues.

Select a task to open a fresh preview on the right with its status, assignee, due date, description and sub-issues. **Activity** loads its comments after the preview opens. Drag the divider to resize the preview; the width is remembered. **Open in Asana** opens the task in Asana.

Choose **Import into Tasks** on a source preview. The normal Tasks composer lets you edit the imported title and description, add your own instructions, and choose priority and agent. **Create task** saves a local Todo without starting a session. Canceled import drafts survive reopening, separately per source and project from manual drafts. Asana has no bookmark step; pick a source and import it directly into a task draft.

Open the created Todo to continue editing its title, description and assignment. Its Asana source link and imported comments remain available even when disconnected; local edits never change Asana. Choose **Agent**, **Model** and **Effort** in Tasks before **Start session**. The opening prompt includes the edited description and added instructions, the source link and parent, and the latest five imported comments (each shortened to 500 characters). Task links in thread headers return to Tasks.

Use **Archived** beside **All tasks** to find and search this project's archived tasks and conversations, including older conversations archived before Tasks existed. Open a card and choose **Restore** to resume its original conversation when available. Known progress is preserved; older entries without saved progress appear as Todo.

Open any Tasks detail and choose **Add subtask** to create a child in a separate dialog. The project and parent appear in its breadcrumb, and canceled drafts are remembered separately for each parent. Subtasks have their own status, description, priority, agent and execution; creation saves a Todo without starting anything. Children remain visible in their status columns with their parent name. A parent shows its immediate subtasks and Done/total count; click a child to open it and use **Parent** to return. Nested subtasks and navigation to archived relatives are supported. Parent and child status/archive choices stay independent. Deleting a parent preserves its children as independent tasks, including their conversations and progress. New subtasks cannot be added to an archived or removed parent.

**Import from MantisBT** opens a native interface matching MantisBT 2.28: charcoal navbar, compact gray sidebar, blue widget headers, status colors and ruled issue tables. **My View** shows open issues assigned to you; **View Issues** shows all open issues in the selected project, loading pages of 100 source issues. Search the loaded issues by number, summary, category, status or assignee, and expand **Filters** to narrow by status. Selecting an issue opens **View Issue Details**, with the metadata grid, description, **Relationships** and **Activities**. **Back to issues** returns to the table, while **Import into Tasks** opens the normal editable Tasks draft. MantisBT uses its own light palette and full-page issue view.

In **My Account**, enter the installation's **Server URL** (for example `https://tracker.example.com/mantis`) and an API Token created in MantisBT's **My Account → API Tokens**. Connect validates the token before saving it under Herdr's home in `data/devkits/mantisbt.json`, independently of Asana. API URLs ending in `/api/rest/` also work. Project bindings are specific to the server and Devkits folder. Resolved issues follow the project's configured resolved-status threshold. Devkits uses only GET requests and supports both Bearer authentication and the bare Token header used by MantisBT 2.28 and earlier.

Imported MantisBT tasks retain their source URL, description, parent and comments offline. Canceled drafts stay separate from manual tasks, Asana imports and other MantisBT servers.

The Files and Git buttons toggle only the right dock. Switching between them keeps the central document; selecting a file, changed file, commit or View Diff opens its content there. Closing a file tab returns to the most recently active tab. Ctrl+Tab / Ctrl+Shift+Tab in file content cycle recent tabs while Control is held. The Threads sidebar is resizable, and each project also remembers its conversation width. Hiding the conversation returns focus to the editor; selecting a thread focuses its terminal. Run reveals its output even when the conversation was hidden.

Parallel panes belonging to one thread are grouped by a bounded connector bracket in the sidebar. Independent threads remain ordinary separate rows. Real child tasks nest below their own parent, including children started from a parallel terminal. Click one to focus its pane; its hover close button closes only that pane. A secondary split pane’s **⋯** menu contains only **Close terminal**; the primary thread’s menu contains only **Close thread**.
